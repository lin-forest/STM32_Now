## 关键修正：`>> 2` 是正确的，我之前的分析错了 ⚠️

### 错误回顾

我（reviewer）最初认为 MT6701 标准 SSI 帧是 `[Status(2) | Angle(14)]`，角度在低 14 位，
所以 `>> 2` 会破坏角度值。

### 实测证伪

| 代码 | 360°旋转观察结果 | 结论 |
|------|-----------------|------|
| `data >> 2 & 0x3FFF` | **1 次** 0→16383→0 | 正确的单圈角度 ✅ |
| `data & 0x3FFF`（不移位） | **2 次** 0→16383→0 | 角度高频溢出 ❌ |

### 该模块的实际帧格式

```
16-bit SSI帧: [Angle(14) | Extra(2)]
               B15←→B2       B1 B0
```

角度在 **bits 15:2**（14 位 MSB 对齐），低位 2 bits 是 CRC/状态/填充。

推导：
```
data >> 2 = [0 0 A13 A12 A11 ... A1 A0]   → 正确的 0~16383 ✅

data & 0x3FFF = [A11 A10 ... A0 X1 X0]
              = angle[11:0] << 2 + X
              → 角度每转 1/4 圈就溢出一次, 360°出现2次 0→16383 ❌
```

### 最终代码

```c
static uint16_t MT6701_ReadRaw(void)
{
    uint8_t tx[2] = {0x00, 0x00};
    uint8_t rx[2];

    MT6701_CS_LOW();

    HAL_SPI_TransmitReceive(&hspi1, tx, rx, 2, 100);

    MT6701_CS_HIGH();

    uint16_t data = ((uint16_t)rx[0] << 8) | rx[1];

    /* 该模块SSI帧: [Angle(14) | Extra(2)]  角度在bits 15:2 */
    return (data >> 2) & 0x3FFF;
}
```

## 经验教训

SSI 帧结构因 MT6701 批次/封装/配置而异。**不要假设帧格式**——用实验确定：
1. 先打印 raw hex `%02X %02X` 看原始字节
2. 转磁铁，分析哪几位变化
3. 再决定 shift/mask
