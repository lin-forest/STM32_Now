## 一、测试指令表

### CAN ID: 0x130 — 关节角度控制

| joint_id | R1 对象 | R2 对象 |
|:--------:|:--------|:--------|
| `0x00` | **J0 DC 电机** (速度) | J0 基座旋转 ⛔锁死 |
| `0x01` | 左舵机 (CH1 独立) | **J1 大臂摆动** (第一关节, TIM4_CH1/PB6) |
| `0x02` | 右舵机 (CH2 独立) | **J2 小臂摆动** (第二关节, TIM4_CH2/PB7) |
| `0x03` | 双爪同步 | **J3 夹爪** (末端, TIM4_CH3/PB8) |
| `0xFF` | 全部 | — |

CAN 数据格式：`[cmd] [joint_id] [value_L] [value_H] [--] [--] [--] [--]`

**R1 关节映射 (2026-07-06 更新)：**
| joint_id | 对象 | 说明 |
|:--------:|:----|:-----|
| `0x01` | 左舵机 (CH1) | 独立控制, 用于校准偏移 |
| `0x02` | 右舵机 (CH2) | 独立控制, 用于校准偏移 |
| `0x03` | 双爪同步 | 按 `GRIPPER_LEFT/RIGHT_OFFSET` 自动补偿 |

| 命令 | cmd | joint_id | value | 说明 |
|:----|:---:|:--------:|:-----|:-----|
| **绝对位置** | `0x11` | `0x01~0x03` | 脉宽 2800~5000 | R1: 1=左, 2=右, 3=双爪同步 |
| **增量** | `0x21` | `0x01~0x03` | 增量值(可负) | 当前值 ± delta |
| **多关节** | `0x12` | mask(见下) | — | 见下文 |

**多关节 0x12 数据格式：**
```
[0x12] [bitmask] [j1_val_L] [j1_val_H] [j2_val_L] [j2_val_H] [gripper] [j0_speed]
```
- bitmask: `0x01=J0`, `0x02=J1`, `0x04=J2`, `0x08=Gripper`
- R1 模式下 J1/J2 无独立控制, bit 0x08 设置夹爪脉宽

### CAN ID: 0x430 — 参数配置

| 命令字节 | 含义 | R1 效果 | R2 效果 |
|:--------:|:----|:--------|:--------|
| `0x01` | 回中 HOME | 夹爪设到 3200 (中位开口) | J1/J2 归零, J3=3200 |
| `0x02` | 设角速度 | 无效果(未实现) | 设置 J1/J2 运动速度 |
| `0x03` | 锁定 LOCKED | 舵机输出冻结 | 舵机输出冻结 |
| `0x04` | 解锁 UNLOCKED | 恢复舵机输出 | 恢复舵机输出 |

### CAN ID: 0x230 — 状态查询

| data[0] | 说明 |
|:-------:|:-----|
| `0x01` | QUERY_STATUS — 触发立即发送一帧 0x330 |
| `0x04` | LOG_START — 开启终端 printf 调试输出 |
| `0x05` | LOG_STOP — 关闭终端 printf 调试输出 |

### 自动上报: CAN ID 0x330 — 状态上报

每 50ms 自动发出，无需查询。

**R1 格式：**
```
[gripper_L] [gripper_H] [j0_encoder_L] [j0_encoder_H] [gripper/200] [j0_speed] [flags] [0x00]
```

**R2 格式（实际代码，2026-07-14）：**
```
[J1_raw_L] [J1_raw_H] [J2_raw_L] [J2_raw_H] [gripper/200] [J0_speed] [flags] [0x00]
```
| 字节 | 含义 |
|:----:|:------|
| 0-1 | J1 raw angle (uint16 LE, 0~16383, MT6701 14bit) |
| 2-3 | J2 raw angle (uint16 LE, 0~16383) |
| 4 | 夹爪位置 / 200 (uint8, 0~25, 对应 CCR 0~5000) |
| 5 | J0 current speed (int8, 当前未用) |
| 6 | flags: bit0=J1_IN_RANGE, bit1=J2_IN_RANGE |
| 7 | 0x00 (保留)

### 左右舵机独立偏移 (实测 2026-07-06)

因机械安装公差，在相同脉宽下左舵机比右舵机更松。通过独立控制测得:

```bash
# 找左舵机(2844=3000效果) → GRIPPER_LEFT_OFFSET  = -156
cansend can0 130#11011C0B00000000    # 左=2844

# 找右舵机(2952=3000效果) → GRIPPER_RIGHT_OFFSET = -48
cansend can0 130#1102880B00000000    # 右=2952
```

最终配置:
```c
#define GRIPPER_LEFT_OFFSET     (-156)  // 左舵机比目标值少156
#define GRIPPER_RIGHT_OFFSET    (-48)   // 右舵机比目标值少48
```

HOME 回中 (`430 01`) 复位独立模式，回到双爪同步。验证:
```bash
cansend can0 130#1103B80B00000000    # 双爪=3000 → 左=2844, 右=2952
```

## 六、R2 舵机臂 —— 完整 CAN 指令集 (ARM_CFG_SET=2)

> ⚠️ **小端 (Little-Endian)**：以下所有多字节数值均为小端编码，即**低字节在前**。
> 例如 J1=90°(900=0x0384) → data[2]=0x84(低), data[3]=0x03(高) → `84 03`。
>
> **关节命名**：J0=基座旋转(⛔机械锁死) · J1=大臂(第一关节) · J2=小臂(第二关节) · J3=夹爪(末端)

### 快速上手指南

> **初始位置**：J1(大臂)=-45°, J2(小臂)=-90°（上电/回中后先到此处）

```bash
# 0. 终端开监听
candump can0 &

# 1. 解锁 (上电后必须先解锁)
cansend can0 430#0400000000000000

# 2. 回中 (J1→0°, J2→0°, J3→3200 开口)
cansend can0 430#0100000000000000

# 3. J1 → 90°
cansend can0 130#1101840300000000

# 4. J1+J2 同步 (J1=90°, J2=30°)
cansend can0 130#120684032C010000
```

#### ③ 多关节同步 (cmd=0x12)

格式：`[0x12] [bitmask] [J1_L] [J1_H] [J2_L] [J2_H] [gripper] [J0_spd]`

| 字段 | 说明 |
|:-----|:------|

| gripper | **uint8, 0~200** → 内部映射到 CCR **5000~3000** (0=全开, 200=安全底线) |
| J0_spd | int8, -100~100 (保留) |

| **回中 HOME** | `cansend can0 430#0100000000000000` | J1→0°, J2→0°, J3→3200(中位开口) |
| **设速度** | `cansend can0 430#02B80B0000000000` | J1+J2 统一 = 3000 (0.1°/s) = 300°/s |
| **锁定 LOCK** | `cansend can0 430#0300000000000000` | `g_servo_active=0`, 舵机冻结 |
| **解锁 UNLOCK** | `cansend can0 430#0400000000000000` | `g_servo_active=1`, 恢复舵机 |

> ⚡ **使用顺序**：上电 → 解锁 `430#04` → 回中 `430#01` → 执行动作

### 推荐测试顺序

> 🎯 **初始位置**：J1=-45°, J2=-90°, J3=3200(中位开口)
>

```bash

cansend can0 130#1101840300000000 # J1→90°
# → 舵机转到约 90°, 串口显示插值过程

cansend can0 130#11013EFE00000000 # J1→-45° (初始位置)

cansend can0 130#1102C20100000000 # J2→45°

cansend can0 130#1102A0F700000000 # J2→-60°
```

## 七、常见问题排查

| 现象 | 原因 | 解决 |
|:----|:-----|:-----|
| 0x330 正常，但 0x130 无反应 | g_servo_active=0 | 发 `430#04` 解锁 |
| 0x330 raw=0/J1=0 | MT6701 未接或 SPI 失败 | 无编码器不影响 PWM 输出 |
| 舵机不动 | 供电不足 / 信号线未接 / 构型不对 | 检查 PB6/PB7 接线, 确认 `ARM_CFG_SET==2` |
| 串口 `[CAN_Rx alive]` | 队列空，未收到 CAN 帧 | 检查 CAN 滤波 / 总线连接 |
| 0x330 接收不到 | USB2CAN 未开 / ACK 错误 | 检查 `ip link show can0` |
| 发送后报 `CAN_ERR: ACK` | 总线上只有 STM32 一个节点 | 开启 PCAN/USB2CAN 提供 ACK |

> 问题：为什么上位机 CAN 没打开时串口报错，打开后报错消失？

### CAN 协议的基本要求

CAN 总线要求**至少两个节点**才能正常通信。每条 CAN 报文发送时，发送节点会在 ACK 槽位等待接收节点拉低总线以确认收到。**没有 ACK = 发送失败**。

### 旧代码行为 (回环发送未删除时)

```
 上位机 CAN 未开              上位机 CAN 已开
 ┌─────────────────┐          ┌─────────────────┐
 │ STM32           │          │ STM32           │
 │  - TX 0x330     │          │  - TX 0x330     │
 │  - 无 ACK       │          │  - 收到 ACK ✅  │
 │  - 持续重试      │          │  - mailbox 释放  │
 │  - mailbox 占满  │          │  - 下周期正常发送 │
 │  → "CAN_TX_FAIL" │          │  → 无报错       │
 └─────────────────┘          └─────────────────┘
```

### 详细流程

**上位机 CAN 未连接时：**

```
Arm_State_Task (50ms)
  ├─ HAL_CAN_AddTxMessage() → HAL_OK       ← 第一帧进 mailbox
  ├─ CAN 硬件发送                ← 无节点 ACK, 重试...
  ├─ 50ms 到, 再次调用
  ├─ HAL_CAN_AddTxMessage() → HAL_ERROR    ← mailbox 仍被占满
  │   └─ 打印 "CAN_TX_FAIL"
  ├─ 错误计数器递增
  ├─ 达到阈值 → HAL_CAN_ErrorCallback()    ← 打印 CAN_ERR
  └─ ...反复...
```

**上位机 CAN 开启后：**

```
Arm_State_Task (50ms)
  ├─ HAL_CAN_AddTxMessage() → HAL_OK
  ├─ CAN 硬件发送 → 收到 ACK ✅
  ├─ mailbox 释放
  ├─ 错误计数器逐渐归零
  └─ 下一周期正常发送, 不再有 CAN_TX_FAIL
```

### 关键配置

```c
.AutoRetransmission = ENABLE   // 无 ACK 时无限重试 → mailbox 永不释放
.AutoBusOff = ENABLE           // 自动从 Bus-Off 恢复
```

这两项叠加导致：**没有 CAN 节点时，发送失败且不可自愈**——这是 CAN 协议的正常行为，不是 bug。上位机 CAN 一开，ACK 恢复，一切正常。

## 四、当前限制

| 限制 | 说明 |
|:----|:-----|
| 无 CAN 节点无法测试 | 必须至少有一个其他 CAN 节点(USB2CAN/PCAN)提供 ACK |
| R1 夹爪无位置反馈 | 当前是开环 PWM 输出，看不到实际夹爪位置 |
| 增量模式 0x21 在 R1 下有符号问题 | `value` 为 `int16_t` 但夹爪是 `uint16_t`，负值回绕 |
